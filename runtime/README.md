# OPC UA Runtime

The OPC UA runtime is a standalone C executable built on [open62541](https://www.open62541.org/) that hosts the OPC UA server. It reads a JSON configuration file generated by the Node.js Control API and exposes the defined address space to OPC UA clients on port 4840.

## Prerequisites

- **CMake** 3.16 or later
- **C compiler** with C11 support (GCC, Clang, or MSVC)
- **Git** (for FetchContent to download dependencies)
- **Ninja** (build system, recommended)

### Linux/macOS

```bash
# Ubuntu/Debian
sudo apt install cmake build-essential git ninja-build

# macOS (with Homebrew)
brew install cmake ninja git
```

### Windows

Install [MSYS2](https://www.msys2.org/) and then from the MSYS2 terminal:

```bash
pacman -S mingw-w64-x86_64-gcc mingw-w64-x86_64-cmake mingw-w64-x86_64-ninja
```

Ensure `C:\msys64\mingw64\bin` is on your PATH, or use the provided build script which handles this automatically.

## Building

### Using Build Scripts (recommended)

**Windows (PowerShell):**

```powershell
.\build.ps1            # Debug build (default)
.\build.ps1 -Release   # Release build
.\build.ps1 -Clean     # Clean and rebuild
```

**Linux/macOS (Bash):**

```bash
./build.sh             # Debug build (default)
./build.sh --release   # Release build
./build.sh --clean     # Clean and rebuild
```

### Manual Build

From the `runtime/` directory:

```bash
mkdir build && cd build

# Linux/macOS
cmake .. -G Ninja
cmake --build .

# Windows (with MSYS2 MinGW on PATH)
cmake .. -G Ninja -DCMAKE_POLICY_VERSION_MINIMUM=3.5
cmake --build .
```

For a Release build:

```bash
cmake .. -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build .
```

The compiled binary will be placed at `runtime/opcua-runtime` (Linux/macOS) or `runtime/opcua-runtime.exe` (Windows).

## Usage

```bash
./opcua-runtime <path-to-config.json>
```

The runtime expects a JSON configuration file as its only argument. This file is generated by the Node.js Control API and contains the full address space definition (namespaces, folders, nodes) and security settings.

### Signals

| Signal   | Platform    | Effect                                      |
|----------|-------------|---------------------------------------------|
| SIGUSR1  | Linux/macOS | Reload configuration from disk              |
| Named pipe | Windows   | Write "reload" to `\\.\pipe\opcua-runtime-{pid}` |
| SIGTERM  | Linux/macOS | Graceful shutdown                           |

## Dependencies

Both dependencies are fetched automatically via CMake's FetchContent module during the configure step — no manual installation required.

| Library    | Version | Purpose                          |
|------------|---------|----------------------------------|
| open62541  | 1.3.9   | OPC UA server stack              |
| cJSON      | 1.7.17  | JSON configuration file parsing  |

## Integration with the Control API

The Node.js Process Manager spawns this binary as a child process:

```typescript
const pm = new ProcessManager('runtime/opcua-runtime', 'runtime/config.json');
await pm.start();
```

The binary path is relative to the project root. The Process Manager handles lifecycle (start/stop/reload) and crash detection.
